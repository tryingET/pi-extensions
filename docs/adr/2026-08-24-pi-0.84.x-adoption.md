# ADR: pi-coding-agent 0.84.x adoption across pi-extensions

Date: 2026-08-24  
Status: accepted (P0 implemented and live-verified 2026-08-24; P1/P2 pending)  
RFC: `docs/project/2026-08-24-pi-0.84.x-adoption-rfc.md` (review rounds 1–2 applied)

## Context

Installed pi moved from 0.84.2 to 0.84.3 on 2026-08-24. Upstream shipped
`session_compact_failed` (#8175) — the exact event we proposed after our tracker
issue was auto-closed NOT_PLANNED by triage automation — leaving stale local records
and a standing observability gap: pi-telemetry attributes ~1,400 of ~1,800
compactions per 30-day window as "stalled" because failure causes were unreachable.
Additional 0.84.1–0.84.3 surfaces (expandPromptTemplates, defaultTools custom-tool
preservation fix, tool_call terminate) intersect several packages. Two review rounds
verified all load-bearing claims against source, corrected a false premise (ASC has
no blocking path; terminate was deferred), and resolved compatibility questions
(pi-session-compaction passes no tools to providers).

## Decision

Adopt the RFC's ranked plan:

1. **P0-A (pi-telemetry):** subscribe to `session_compact_failed`. Correlate via
   composite `(sessionId, compactionSeq)` keys — seq is context-scoped, resets on
   session replacement, dashboards group by sessionId before aggregating. Exhaustive
   terminal-state machine with single-canonical-outcome rule; aborted+willRetry is a
   separate recoverable class excluded from hard-failure counts. Introduce a record
   schema-version field; historical stalled attributions are never rewritten.
   Orphan-rate panel ships with the change; alert promotion deferred one quarter.
   Ownership-on-failure in pi-session-compaction releases all claims regardless of
   `fromExtension`.
2. **P0-B (truth repair):** update #8175 in the issue-tracker via plain `ak issue`
   (DB wins; STATE.json only via `issue-export-state.sh`/`issue-sync.sh`); tracker AK
   issue authored first; monorepo maintenance-notes §2 edit second, referencing it.
   Upstream comment (RFC Appendix A) requires explicit operator approval per
   Decision 68 before posting.
3. **P1:** pi-autonomous-session-control reaffirms non-expansion for
   action-dispatched user messages citing the new option; `terminate` remains
   deferred (no blocking path exists; own RFC prerequisite).
4. **P2:** pi-prompt-template-execution adopts explicit `expandPromptTemplates`;
   five tool-registering packages pin defaultTools custom-tool survival with tests.
5. **Execution authority:** AK tasks scoped per work package precede implementation;
   package-local validation contracts run before merge.

## Consequences

- Compaction failures become causally attributed; stalled-unknown shrinks to
  genuinely severed events (host crash, session-boundary retry).
- Telemetry consumers must partition on schema version; rollback is safe because
  emission is additive-only and unknown kinds are ignored by version-0 consumers.
- ASC behavior does not change in this adoption cycle; blocking guardrails +
  `terminate` stay out of scope until their own RFC.
- Tracker/docs no longer contradict runtime state; external effects remain gated.

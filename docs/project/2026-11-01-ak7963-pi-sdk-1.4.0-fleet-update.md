The two failed `full.sh` runs each hit a different test, and neither is caused by this change.
`dispatch-subagent-lifecycle-control` imports no Pi SDK and did not recur in 50 runs on either tree
(AK8286). `workstation-scheduler-adversarial` builds a permit from two `Date.now()` calls against a
1000 ms limit (AK8287). No manifest or lock changed since the security scan, so its results stand.
Packing still reads the working tree rather than an immutable export (AK8285).

**Rollback.** Reverting the five commits from the tip gives a tree identical to `main`. Both hosts use
session format 3, and 1.1.0 read back a session 1.4.0 wrote. Host 1.1.0 stays installed.

**Security.** `depviz --include-dev` exits 2 before and after, on 394 existing findings: 0 introduced, 0
severity increases, 0 licence changes. It reads package locks, so it cannot see `runtime.lock`. `npm audit`
on that closure shows no high and 2 moderate, both `minimatch`. The side-by-side Pi CLI prefix still has
`undici` 8.10.2: 1 high and 2 moderate. A scan shows no known finding was added; it does not show the
update is secure.

**Exception.** The contract requires RED on the current installer, which hardcodes `/usr/bin/node` and
fetches unlocked. The operator allowed that for (a) and (d) only, in scratch.

**Not proven.** Live behaviour on Node 26.13.0, which `pi` on `PATH` uses, a paid provider, a real TUI, and
anything about a default-host reinstall. Tests for the fixes from the pre-commit code review were written
with those fixes, so they had no separate RED. The unit suites still run on `undici` 8.10.2, because only
the installed runtime carries the override.

## Rollback

- **Code:** the pin and adaptation commits revert as a set.
- **State:** both versions use session format 3, and 1.1.0 read back a session 1.4.0 wrote, with messages,
  model and thinking level intact.
- **Host:** 1.1.0 stays installed. Pointing `~/.npm-global/bin/pi` back restores it.

## Unrun and open

- Paid provider and native LLM acceptance: not run, no such authority.
- Upstream's own suite at the tag: not run, see S1.
- Runtime re-observation through runtime-trace-insights: not run. The dependency is the host itself, so
  the host-reporting probe answers the question more directly.
- `subagent-attachment-duplicate-listeners` failed once in the first bumped run. It did not recur in 240
  runs under 24x parallel load on either tree or in any later run. Not attributed to 1.4.0, not explained.
- `pi-modes` still declares `>=1.1.0 <2.0.0`, and the suite now proves only 1.4.0. The floor stays so that
  rollback to 1.1.0 is not refused; raise it once 1.4.0 has settled.

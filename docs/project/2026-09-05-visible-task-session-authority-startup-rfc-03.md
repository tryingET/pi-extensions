## 2. Problem, alternatives and selected boundaries

The discovery failure was real: an ad hoc shell script was reinvented despite an existing checked-in launcher. Source investigation additionally found independent safety gaps: native claim atomicity does not span companion facts, nominal reads may maintain storage, optional hooks do not cover all execution paths, provider transports/auth have distinct effects, and existing writers do not participate in new reservation state.

| Alternative | Strongest case | Decision and cost |
|---|---|---|

| Preparation/inspection only | Honest refusal while prerequisites are absent | Current holding posture, not completed launch functionality. |

Retain exclusions: parent-held transfer, auto-unclaim/reclaim/relaunch, candidate creation/adoption, standing-agent identity, remote/multi-user/hostile same-UID assurance, arbitrary binary/module/env overrides, batch/multi-task requests, fork/resume/import and continuous revocation. ## 4. AUTH-01/02 — actual owner-held startup interval

### 4.1 Native facts and new owner contract

B keeps asserted-local identity and one native fresh-task claim. Require explicit scope and ordinary non-FCOS/non-specialized execution. No default-off task begin or delegation protocol is activated. Bind canonical AK instance/task/repo, task and companion revisions/digests, dependency status and decision link membership/roles/relevant state, effective temporal deferral truth, exact intended child/attempt, owner policy/pin/protocol, reservation and envelope/profile digests. Blocking-ID lists or task version alone are insufficient.

The **new AK-owned `startup_interval_v1` design contract** encloses no-maintenance authoritative reads, one native claim, independent readback and the host's local admission transition under actual canonical lock custody. The label is not an installed command, promoted ontology or authority token. It is neither baseline CAS nor continuous revocation. Owner-side code/access-mode changes are required after ADR; today's gate must not be bypassed or presented as equivalent.

Native claim may commit and then return an error. Unknown claim outcome denies task release and remains unresolved; matching later snapshot is not replay proof. Check exact expected own-claim version `v -> v+1`, actor/claimed_at/lease, unchanged intended task/scope/repo and independent companion/dependency/decision facts. Time continues under the lock: validate evaluated deferrals and lease bounds, refusing relevant temporal drift rather than claiming a frozen clock.

Ordinary nominal reads can perform maintenance or exact-ID task-table repair. The closed owner mode must refuse repair-required/noncanonical admission and suppress/deny repair fallback on its native-claim path while preserving native claimability. Account explicitly for permitted claim/receipt and elapsed-deferral normalization. Unexpected companion change denies. Separate storage repair stays with the existing maintenance/incident owner; no current database repair is authorized here.

### 4.2 Inversion-free prepared-host protocol

| Phase | Exact owner action and invariant |
|---|---|
| Reservation | Little-helpers takes its short namespace mutex, checks both conflict domains and durably reserves/spawn-intends; releases mutex before owner calls or spawn. Reservation persists throughout uncertainty. |
| Open / prepare | AK supervisor opens/validates the canonical permanent DB lockfile **without locking**, deliberately passes the same open-file description (OFD) and private bound channel to the sealed host. Host finishes allowed resource/provider-metadata initialization, empty SDK construction, wrappers and frozen inert envelope **outside the DB lock**. |
| T0 | After PREPARED, supervisor acquires canonical Linux flock on that shared OFD, drains prior gated calls and validates pin/policy/identity. Host retains an actual reference to the locked description. No arbitrary FD, recursive ordinary gate or caller skip-lock. |
| Authoritative interval | AK performs the closed no-maintenance baseline, one native claim and independent readback. All cooperating canonical DB invocations are excluded, including companion/recovery writers and nominal reads. No model/tool/network task effects or resource initialization in this interval. |
| T1 | Host durably binds exactly one admitted envelope/baseline/claim to this incarnation, or irreversibly denies admission. Immutable private T1 sidecar binds attempt/incarnation/request, baseline/effective-envelope, exact claim tuple, reservation, pin/policy/protocol and no-dispatch-yet. Supervisor verifies matching one-shot durable result. **T1 is not prompt execution or mere receipt of a supervisor proposal.** |
| T2 | Explicit supervisor unlock only after validated durable admitted T1, or irreversible denied T1 for orderly denial closure. No namespace mutex is acquired inside the AK interval: sidecar is single-writer; namespace history projection follows unlock. |
| CLOSED / release | On successful private, phase/incarnation-bound nonpersistent CLOSED, host rechecks outcome/deadline, closes private descriptor as prescribed and projects remaining state outside the DB lock. Admitted outcome enables exactly one guarded literal prompt; DENIED/unknown/missing/stale CLOSED cannot. Failed post-unlock persistence/lease check denies and retains claim/exclusion. |

Authority-writer exclusion spans **T0–T2**, not just T1. After T2 the affected-writer custody rule below applies even while CLOSED/first prompt is pending. No promise of continuous freshness or no-authority-change-until-provider-send is made. The known lease deadline and local denial/profile/lineage remain dispatch checks.

### 4.3 Failure and custody rules

Use the supported Linux shared-OFD flock semantics, not interchangeable process-associated fcntl semantics. Permanent inode; no unlink/recreate or alternate lock domain. Explicit `LOCK_UN` on any shared reference unlocks despite other holders: trusted helper code must restrict it to the closed protocol. No unconditional-finally, timeout, EOF or PID-based unlock.

Supervisor death before unlock leaves host-held custody and no prompt. Unlock then death before CLOSED leaves host denied/unresolved while unrelated AK may resume. Host death before T1 cannot select success unlock; after T1 it does not prove execution/retirement. If all OFD holders die, the kernel releases the lock, but durable reservation/claim/effect uncertainty persists. Missing/corrupt/failed T1 or unknown native result never enables release or resend.

Descriptor/channel stay private to owner/host operations with immediate CLOEXEC after intentional inheritance and no tool/provider/UI leakage. Surviving native operations must be accounted for; no helper has task-model capability. Startup deadline causes local terminal denial before lawful closure, not age-expiry of custody. A stalled live holder can block global AK access: provide an out-of-band DB-free inspector and owner recovery, not a lockfile delete. This availability cost is explicit and does not suspend today's separately authorized database incident-recovery route.

### 4.4 After T2 and owner-only recovery

Positive AK enrollment inventories all DB access/trigger routes: task lifecycle/scope/companions/dependencies/decisions/repo identities, imports/restore/composition, explicit recovery, maintenance/direct adapters, policy/binary/DB replacement and queued/restarting callers. Source shows explicit DB-wide release-expired semantics; it does **not** prove an installed periodic daemon. Actual triggers must be established, not invented or inferred absent.

After startup, unrelated AK work may proceed. For the enrolled authority-input set, affected writers use **stop-and-dispose-before-change**: host future-dispatch closure and started-effect disposition precede relevant mutation/reassignment. If an operation cannot distinguish affected from unrelated/bulk work, suspend that route/trigger. The simple v1 contract suspends DB-wide lease-recovery triggering while it could touch any enrolled active/unresolved attempt, using owner-directed exact-task recovery instead; queued/in-flight/restart paths and reinstatement criteria are explicit. This may accumulate unrelated expired claims. A startup-only pause is insufficient.

Claim-success/message-denial recovery first obtains host/effect closure outside the global lock. A **new owner recovery interval** then compares preserved exact claimant/claimed_at/lease/task-version/repo under custody, performs one explicit owner-native unclaim if still matching, and retains custody through result/readback. Non-CAS unclaim is acceptable only under that actual interval. Drift/uncertainty stops without retry. Reassignment must not be undone to clean up the old attempt. Retirement requires three distinct outcomes: host no future dispatch, started effects disposed, and AK claim resolved. Completion/lease/ACK/window facts alone do not release the operational reservation.

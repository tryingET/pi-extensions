# Source-evidence acquisition posture — 2026-07-26

## Policy

**Use existing evidence unless a named context decision is blocked by a missing fact. Acquire only that fact from its owner. Provider availability is never a reason to acquire, rank, register, or wire it.**

Apply four separate gates:

1. **Need** — name the blocked user decision and the missing fact. If neither is concrete, stop.
2. **Acquisition** — choose the least-cost source-owned way to obtain that fact; price latency, bytes/tokens, eligibility discovery, staleness, trust, and maintenance.
3. **Selection value** — prove that a specified ranking, budgeting, or abstention rule improves the context decision. Valid input is not proof of useful selection.
4. **Operational authority** — require quality, cost, trust, and runtime approval together. Passing one gate never passes the next.

This replaces provider adoption as the decision frame.

## `source-list.v1` disposition

`source-list.v1` is a valid deterministic factual-inventory capability owned by Agent Scripts. The completed program does **not** establish that it is useless, or that it has net value for context packing.

- A caller needing tracked-source inventory or authored factual fields may invoke Agent Scripts directly, outside pi-context-packer.
- No pi-context-packer product/runtime provider invokes, acquires, ingests, ranks, registers, or wires `source-list.v1`, including in response to a manual or explicit caller request. Retained source-selection experiment code and artifacts are audit/reproduction surfaces, not an integration or standing experiment authorization.
- The threshold-1 `source_list_positive` rule is retired: it changed no selection in the valid v4 population.
- There is no metadata campaign, threshold-tuning path, automatic-invocation path, or standing successor experiment.

An explicit request changes neither ownership nor authorization.

## Reopening boundary

Do not reopen work for `source-list` itself. A new case begins only with an observed context failure whose missing fact cannot be supplied by the objective, safe seeds, docs-list, SCI, current-session evidence, or a cheaper read-only analysis.

Before experiment design, require an independently derived policy hypothesis, the decision the result would change, and separate authority. Multi-repository or one-shot evidence work is risky/expensive: route its need, integrity plan, decision impact, and owner boundaries to AK/decision authority. This document creates no task and authorizes no experiment or production change.

## Owners

- Pi-context-packer owns acquisition, ranking, budgeting, and context-packing value claims.
- SCI owns its separate semantic evidence; its results cannot rescue a failed source-list policy.
- AK owns task, decision, and evidence lineage.

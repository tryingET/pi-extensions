## Many of the greats — actual disagreement and decision

Question: what evidence permits changing a working asynchronous input surface without sacrificing
agency, availability or progress?

### Mode1 — separate strong cases

- Formal concurrency: correctness belongs to identity and happens-before, not examples. Its
  premises are revocable grants and reused handles. It sees the late release/FD-reuse histories
  that broad success counts miss; finite GUI demonstrations cannot establish universal safety.
- Incremental TDD: executable local counterexamples and minimal changes are the strongest practical
  control on mistakes. Its premise is limited knowledge. It sees speculative rewrites and enormous
  untestable plans as greater immediate risks than a bounded incompleteness statement.
- Human-interface agency: a surface is correct only if the person retains control of typing and
  receives the exact intended target. Removing hover maximizes refusal but destroys the accepted
  workflow; the user cost cannot be abstracted into a passing safety predicate.
- Rollback-first reliability: running bytes and recoverable operations are the product. Its premise
  is that deployment/config/process drift defeats correct source. It sees irreversible effects
  hidden by an otherwise green implementation story.

### Mode2 — confrontation

- Universal safety versus finite TDD is a real contradiction of proof strength. No finite seed
  count becomes universal. TDD wins the next change size; concurrency wins counterexample design.
  Residual exhaustive scheduling proof remains absent, not silently declared unnecessary.
- Fail-closed input versus agency cannot both dominate indiscriminately: disabling capture refuses
  all mistakes but also all intended use. Exact admitted, bounded capture is required; deleting hover
  is not a valid repair.
- Immediate source progress versus rollback-first operations conflict only if source and runtime
  are conflated. A qualified source slice can land while the live pair remains protected. For an
  actual switch, reliability dominates and demands exact GUI/startup/rollback evidence first.

### Mode3 — contextual dominance

Choose contextual dominance, not fake synthesis: TDD governs local repair size; concurrency governs
adversarial traces; agency governs accepted interaction; reliability governs live adoption. Practical
consequence: repair the test instrument now, test a real private compositor next, do not perform a
broad ownership rewrite or live switch merely because source tests pass. Universal scheduling and
physical-backend coverage remain explicit unresolved limits.

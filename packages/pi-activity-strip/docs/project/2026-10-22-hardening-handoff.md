## Executable Gherkin-style red–green TDD

These are **scenario seeds, not completed or executable proof**. Turn them into the existing test stack's executable Given/When/Then checks, or use an already-adopted runner. Do not add a dependency merely to obtain Gherkin syntax.

```gherkin
Feature: Durable, predictable activity ribbon
  Scenario: Normal startup uses the approved durable pair
    Given an approved integrated controller and matching receipted native panel
    When the normal entrypoint starts in a fresh isolated profile
    Then the expected build and private protocol are running
    And no temporary task-worktree path is required
    And the documented compatible rollback can be exercised

  Scenario Outline: Presentation changes do not revoke identity
    Given two admitted publishers share one terminal and <mode> owns the keyboard
    When ordinary activity updates reverse their presentation order during NULL focus
    Then the source identity epoch and ownership remain unchanged
    Examples:
      | mode     |
      | hover    |
      | explicit |

  Scenario: Late permission cannot take the keyboard
    Given a hover request exists for one exact owner and interaction lifetime
    When the pointer leaves or that owner is revoked before the grant arrives
    Then the old grant cannot capture keys or expand the surface
    And an old cancellation cannot release a newer explicit claim

  Scenario: Enter survives its own release but not a changed workspace
    Given a listed-target jump was accepted from an exact source context
    When its inactive acknowledgement arrives before restored source focus
    Then the exact target is focused once if fresh source and workspace facts still match
    But if fresh facts show another focused workspace no focus action occurs

  Scenario: Hover typing returns agency
    Given an eligible agent window and a real pointer hover admitted by the controller
    When a listed window number is typed and Enter is pressed
    Then that exact window receives focus and subsequent typing
    And leave, Escape or idle clears even a nonempty hover query

  Scenario: No physical display is required for the isolated GUI lane
    Given the operator compositor has no connected output
    When the approved owned headless GUI runner executes the interaction suite
    Then real input, focus and layer behavior are checked in its private compositor
    And no operator window, runtime socket or accessibility bus is taken over

  Scenario: Diagnostics explain state without exposing text
    Given active, hidden, expired and incompatible runtime states
    When read-only diagnostics are requested
    Then build, protocol, reason and ownership facts are accurate
    And typed text, prompts and credentials are absent
```

### Many of the greats — question and separate schools

Question: which evidence permits improving the ribbon without destroying accepted agency?

Mode 1 — steelmen:
- Formal concurrency: identity and happens-before are the specification. Premise: asynchronous
  grants/releases/focus can interleave. Strongest case: safety must hold for every admissible
  trace; happy-path GUI proves little about late callbacks. Sees stale authority others miss.
- Beck-style incremental TDD: smallest executable failure earns the smallest change. Premise:
  local feedback and reversibility constrain mistakes. Strongest case: one failing mechanism
  is more actionable than an untestable generalized redesign. Sees speculative complexity.
- Human-interface agency: operator retains ownership of typing and exact intent. Premise:
  input capture is an effect with a real human cost. Strongest case: disabling hover for easier
  proof is a product regression even when tests improve. Sees costs abstract states omit.
- Reliability/rollback-first operations: the running qualified artifact is the product.
  Premise: deploy/build/config drift can defeat correct source. Strongest case: unsupported
  rollback and incidental promotions are worse than delayed integration. Sees lifecycle risk.

Mode 2 — confrontation:
- Exhaustive concurrency vs incremental examples: finite examples cannot establish universal
  safety; universal claims outrun this finite implementation/test budget. Residual tension
  stays explicit. Use bounded generated traces and independently specified checks, not proof claims.
- Input agency vs fail-closed capture: disabling capture maximizes refusal safety but violates
  accepted hover. The contract requires bounded admitted capture, not elimination.
- Startup availability vs artifact exactness: silent fallback keeps something running but cannot
  promise the selected pair. Exactness dominates selection; it does not authorize killing a
  healthy retained runtime. Failing a new launch is distinct from replacing an existing one.

Mode 3 — contextual dominance, not fake synthesis: artifact exactness dominates startup;
agency dominates interaction acceptance; TDD governs change size; concurrency governs adversarial
trace design. Runtime qualification dominates claims of delivery. Exhaustiveness remains unproven.
Practical consequence: first repair binding selection; build trace safety net before refactoring;
keep real GUI and physical-backend limits explicit; never delete hover to satisfy an oracle.

## Behavior and implementation

- The screen-top ribbon is eligible only on the focused workspace with admitted cards and
  exact focused agent-window ownership. Browser, Obsidian and arbitrary non-agent focus hide
  it; missing/ambiguous facts fail closed. App-id/title deny-lists are not used.
- Focus events update eligibility immediately against admitted card/window placements, before
  slower polling can finish. Workspace changes, invalid focus facts, stream failure, and changes
  or closure of the exact owning window revoke eligibility. A stale focus event cannot re-admit
  invalidated identity before a new full projection. Loss or ambiguity of the admitted owner
  also revokes eligibility, even if another window's cards remain or the panel owns the keyboard.
- Explicit keyboard entry reserves a revision-bound request **before** sending the command.
  This admits Niri's actual NULL focused-window state during panel keyboard ownership without
  self-hiding. Known non-agent focus dominates late panel acknowledgements. Entry is immediate
  against current projection/event facts: there is no asynchronous command waiting to grab keys
  after returning failure. Hidden and click-through surfaces reject entry.
- Hover requests neither exclusive nor on-demand keyboard mode and captures no search keys.
  Only actual mapped pointer presence admits hover messages. GTK selection alone does not
  expand a card; explicit keyboard navigation still does.
- Hide, loss of keyboard ownership, and pointer leave outside explicit keyboard mode clear
  hover/brand/directory/search/selection/request state and revoke timers and two-frame scroll
  callbacks. Hidden resize paths remain compact and keep the exclusive zone disabled. Returning
  starts collapsed unless actual pointer input or a new explicit shortcut engages it.
- Compact height 84px, 8px insets, expanded minimum 276px, theme/CSS and identity/hidden-tab
  activation mechanisms are unchanged. No CSS or design-token files changed.

Key production surfaces: `src/common/workspace-view.mjs`, `src/native/{focus-visibility,
keyboard-entry,panel-projection,workspace-events,main}.mjs`, and
`native/panel/src/{interaction,app,card_view,runtime}.rs`.

## Current repair — complete-cache production admission revalidation

Third inspection reproduced a different-window conflict: after window 44 established exact
ownership, unfocused window 45 claimed the same Pi identity. The prior event path requested a
poll but revoked only if the changed window itself was the owner. Eligibility therefore remained
true before that poll, including reserved NULL ownership and late acknowledgements.

The current Node implementation removes the local Pi-title regex/proof normalization entirely:

- `placement.mjs` caches the complete window inventory and raw publisher facts from full
  reconciliation. Open/change events replace their window, close events remove it, and
  `WindowsChanged` replaces the inventory. Empty inventories clear the cache; malformed or
  duplicate window ids cannot establish a valid cached view.
- Cached admission uses the **same** `resolveWorkspaceView` production resolver as full
  reconciliation, with all cached windows and established sources. It therefore applies the
  existing global ambiguity, Pi legacy/surface, non-Pi suffix, host and visibility rules rather
  than introducing another title-identity heuristic.
- On **every** changed-window event, `workspace-events.mjs` revalidates the current exact owner
  against that canonical cached projection, regardless of the changed window's id or the
  work-scheduling result. A lost/ambiguous/different visible card revokes synchronously before
  requesting async reconciliation. Close/full-inventory events also revalidate. A focus transfer
  validates its candidate before publishing, so stale non-owner cards cannot briefly re-admit.
- Revalidation only revokes; conflict disappearance, reopening an id, stale focus and late panel
  acknowledgement cannot re-admit invalidated context. A new full projection must establish it.
- Scheduling compares canonical admission/card-placement results, not display-title shapes.
  Unchanged genuine Pi prefixes and unrelated browser titles/moves do not hide the strip or
  request a poll. With unknown source facts, scheduling conservatively retains full title data
  and ownership checks fail closed. Existing source/host rules remain the admission authority.

Integrated production-path regressions establish ownership **before** introducing a second
claimant. They cover Pi 8-hex token-only, 32-hex token-only, surface-bearing identity, and Claude
8-/32-hex exact suffixes; each runs normal and reserved-NULL focus through changed, newly opened,
and complete-inventory/other-workspace conflict paths. They check immediate hide/shortcut
rejection, late acknowledgements, stale focus, zero cards in a fresh full projection, removal
without stale readmission, full-projection recovery and conflicting same-id reopening. Additional
cases cover owner workspace moves and close/reopen, unrelated browser titles/moves retaining
eligibility, and transfer to a stale non-owner card without an optimistic eligible frame. Earlier
Pi-prefix and Claude-hex regressions remain green.
